# Agent 批量整理计划与执行报告

## Goal

让 Agent 为不同文献提出不同标签和分类归属，并将用户审阅过的明确计划安全执行到本地 Zotero。

## Background

归属父任务 R3-R7。现有 `item tag batch` 是基于本地检索结果的统一标签操作，执行走 Web，不能表达每篇不同的标签/分类决策。单条本地操作已具备版本冲突及回读保护，但没有跨条目的冻结计划与执行证据。

## Requirements

- B1：接收显式 item key 及各条目的标签增删、分类成员增删/移动；输入限制为单实例单库普通条目。不把模糊名称当对象身份。
- B2：生成包含完整目标集合、每条本地版本、before/after、分类名称/key、动作数、条目数的可保存计划。确认时执行该计划，不重新跑搜索扩大集合。
- B3：同一条目的标签和分类变更合为一次条件更新；重复 item key、互相矛盾的操作和不支持字段在预览阶段拒绝。
- B4：默认最多影响 50 条；超限在任何写入前停止。提高上限必须显式指定并反映在审阅结果中，不截断后静默执行。
- B5：先校验全部目标和计划完整性，再依次提交；每次提交仍检查版本。首次失败、冲突或未知结果停止剩余写入。
- B6：输出逐项及聚合结果，区分 applied/unchanged/failed/conflict/unknown/verification-failed/not-attempted。不能声称批次具有跨条目原子性。
- B7：执行记录写明目标、动作、before/after、提交前后本地版本与结果；提交中断可识别待核查项。不存授权 key。
- B8：成功项不自动回滚；未知项不盲重试；重新执行或补偿必须重新读取、生成计划和审阅。
- B9：Agent 工作流先提出有限词表与分类理由，对证据不足条目保留人工复核；执行器不负责调用模型或判断语义。

## Acceptance Criteria

- [x] B-AC1：3 个以上合成条目具有不同标签和成员变更，预览零写入，确认后每条最终状态匹配计划。
- [x] B-AC2：改动计划内容、实例/库或任何条目版本后不能静默执行；新增检索命中不影响原计划。
- [x] B-AC3：51 条默认上限拒绝且零写入；显式提高并审阅后允许；重复 key、混库、非法动作、冲突动作拒绝。
- [x] B-AC4：第 2 项失败/未知时，第 1 项成功保留，第 3 项标为未执行；记录与 API 状态一致。
- [x] B-AC5：对同一条目使用一次 PATCH；其他标签类型、分类、字段、children 和附件不变。
- [x] B-AC6：无权限、401、超时、回读失败、报告持久化失败及进程中断有明确证据与停止行为；无自动重放或回滚。
- [x] B-AC7：旧 Web 批量命令行为不变；JSON 状态计数、非成功退出行为和 skill 解读一致。
- [x] B-AC8：完成 A → B → C 的隔离库端到端真实验收，自动化与真实故障覆盖分别列出。

## Out of scope

分类创建混入同一批次、跨库事务、并发写入、自动重试/继续失败项、自动回滚、通用恢复调度器、后台监听、LLM 服务、全库自动搜索并确认。

## Dependencies / status

依赖 A 的标签计算与写入；B 提供端到端测试所用分类，但执行只接收已有 key。已获批准并实施，隔离桌面核心验收通过，进入 review 待提交收口；A/B 接口若有实质变化，须更新本任务设计并重新审阅。
