# Agent 驱动的 Zotero 本地分类与标签完善

## Goal

让 Agent 在不依赖 Zotero 云端同步或 Web API 凭据的情况下，将明确的标签和分类决策安全写入本地 Zotero。Agent 负责阅读文献、判断与说明理由；CLI 负责确定性校验、预览、执行和结果验证。

## Background

- 用户于 2026-11-02 请求根据现状分析创建完善的 Trellis 任务；授权范围是创建与规划，不是实施或操作真实文献库。
- 本地分类成员与字段/作者更新已实现，基线见已归档任务 `10-13-zotero-local-content-operations`。
- 标签增删、批量标签、分类创建当前均依赖 Web API；本地 SQLite 始终只读。
- 本轮 doctor：SQLite 可读，Local API 不可达，Web 凭据缺失。此为环境快照，不是未来验收依据。
- 源码、官方协议和历史真实验收的证据边界见 [research/current-state.md](research/current-state.md)。

## Requirements

| ID | 用户可观察的要求 | 归属 |
| --- | --- | --- |
| R1 | 单条文献可在本地新增/移除指定标签，其他标签及类型保持不变 | 子任务 A |
| R2 | 可在本地创建根分类或已有父分类下的子分类，明确返回分类 key | 子任务 B |
| R3 | Agent 可提交一组显式 item key 的不同标签/分类决策，用户先检查完整差异再执行 | 子任务 C |
| R4 | 确认绑定实例、库和当前本地版本；预览后数据变化不得静默覆盖 | 所有子任务 |
| R5 | 结果区分未执行、无变化、成功、冲突、失败、提交未知及回读失败；不把 envelope 成功等同于写入成功 | 所有子任务 |
| R6 | 批量执行有默认数量上限、逐项结果和中断证据，失败不自动扩大范围或切换后端 | 子任务 C |
| R7 | 自然语言工作流与双语文档准确说明能力和限制，现有 Web/connector 行为兼容 | 所有子任务 |

共同边界：

- 新增本地写操作必须显式选择 local。SQLite 不可写，connector 仍仅导入；Web 默认行为不改。
- 预览和无变化操作不请求授权；实际授权由用户在 Zotero 中完成，不自动点击。
- 标签和成员操作首版沿用非回收站、顶层普通条目边界；仅同一实例、同一库。
- 保留条目 key、其他字段、其他分类、children 和附件；分类移动不等于移动附件文件。
- 不强迫使用联网模型或 embedding。用户的分类词表与决策由 Agent/用户提供。

## Acceptance Criteria

- [x] AC1 / R1：无 Web 凭据时，本地标签新增/移除回读一致；已有标签类型和无关内容保持不变。
- [x] AC2 / R2：根分类、子分类创建及返回 key 可在 API 与 UI 核对；重复名、父分类失效或版本变化不会误创建。
- [x] AC3 / R3：合成条目可按各自不同的决策完成“标签 + 分类归属”，目标集合与审阅计划完全一致。
- [x] AC4 / R4：预览零写入；错误实例/库、过期版本、拒绝授权和只读组库均有明确结果；无后端 fallback。
- [x] AC5 / R5-R6：注入中途失败/提交超时后，已成功、未知、失败、未执行条目可区分；不会盲重试或声称全成功。
- [x] AC6 / R7：现有 Web 命令回归、just ci、双语文档构建和 canonical skill 镜像检查通过（本轮证据见 validation.md）。
- [x] AC7：独立 Zotero profile + data 的真实授权、写入、UI、重启验收完成；自动化/mock/真实证据分列。
- [x] AC8：新能力的文档和 skill 描述与实现一致；未完成子任务不提前宣传为支持。

## Out of scope

直接 SQL 写入、修改全局配置、自动云端同步、插件/bridge/MCP 服务、内置 LLM 分类器、标签本体管理、整库自动清洗、跨库移动、批量创建分类树、本地分类删除/重命名、笔记/合并/附件写入。
不实现跨条目原子事务、自动回滚或通用断点恢复；报告提供人工复核与另行生成补偿计划所需证据，补偿仍须重新读取和预览。
